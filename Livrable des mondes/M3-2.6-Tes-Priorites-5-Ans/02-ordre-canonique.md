## Pourquoi le mélange est sans objet (justification complète)

1. **Pas de séquence d'items** : la quête ne présente pas N questions l'une après l'autre — elle
   présente UNE répartition. Le mélange existe pour contrôler l'ordre de passation d'items
   séquentiels (ancrage positionnel, enchaînements) : ici, il n'y a **rien à mélanger**.
2. **Pas de dimensions à alterner (c1, c4)** : `dimension = null` sur les 5 axes — l'arbitrage EST
   la structure (cinq horizons vus d'un coup) ; une « distance intra-dimension » n'a pas de sens
   sans passation séquentielle.
3. **Pas de trames (c2, c3)** : quête déclarative directe — 0 trame ▲ (`n_trames = 0`).
4. **Pas d'orientation D/I (c5)** : hors Likert — rien à alterner (constat documenté : la bornée
   « run max 2 » n'est même pas atteignable, il n'y a rien à mesurer).
5. **c6 — ordre de passation ≠ ordre des codes** : sans objet de fait — l'ordre d'affichage des
   axes n'est pas un ordre de réponses (tous les curseurs vivent sur le même écran). L'ordre
   canonique 01 → 05 (carrière · famille · liberté · stabilité · projets personnels) est un ordre
   de LECTURE (du plus porté vers le plus personnel — mission V8.B), documenté comme partie du
   protocole.

## Ce qui reste contrôlé malgré l'absence de mélange

| Contrôle | Dispositif |
|---|---|
| Ancrage positionnel | neutralisé par nature : les 5 curseurs se règlent librement, aucun n'est « répondu avant les autres » |
| Effet de suggestion | neutralisé par la mécanique : aucune valeur par défaut, aucun exemple affiché (01, décisions n° 3) |
| Uniformité du protocole | écran identique pour tous ; la somme verrouillée garantit une répartition COMPLÈTE (aucune donnée partielle) |
| Reproductibilité | l'ordre canonique d'affichage est figé dans ce fichier ; tout ré-ordonnancement exigerait une Fiche de Mutation |

> Note d'honnêteté : l'ordre canonique d'affichage (personnel → partagé) est une décision de
> composition (domaine réservé [9] — proposition), À VALIDER PAR LE COMITÉ.
