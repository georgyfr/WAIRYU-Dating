# RIO-04 — Q4 « Notre danse » (croisement attachement)

> Premier croisement à deux du programme : les types d'attachement des deux
> rives produisent une configuration nommée. **Zéro verdict, zéro compatibilité
> chiffrée** — la danse est décrite, jamais notée.

## Les 4 types d'attachement (seuil 2,61)

```
SEREIN      : sA < 2,61 ET sB < 2,61
PRÉOCCUPÉ   : sA ≥ 2,61
DÉTACHÉ     : sB ≥ 2,61
EN ALERTFEU : sA ≥ 2,61 ET sB ≥ 2,61
```

## La table symétrique des 9 configurations

`(type_p1, type_p2) → config` — table symétrique (la danse de A avec B est
celle de B avec A) :

- BASE SEREINE (SEREIN × SEREIN)
- DANSE QUI TOURNE (PRÉOCCUPÉ × DÉTACHÉ)
- FEU CROISÉ (EN ALERTFEU × EN ALERTFEU **ou** PRÉOCCUPÉ × PRÉOCCUPÉ)
- DISTANCE POLIE (DÉTACHÉ × DÉTACHÉ)
- MIXTE SEREINE-POURSUITE / -RETRAIT / -FEU
- MIXTE POURSUITE-FEU · MIXTE RETRAIT-FEU

**Bug documenté D-Q4-1** : clés dupliquées rendaient MIXTE POURSUITE-FEU
injoignable au run initial — corrigé.

## Les mécaniques calculées

### Percentiles (repères D-SIM)
SEREIN **25** · PRÉOCCUPÉ **70** · DÉTACHÉ **20** · EN ALERTFEU **85** —
repères internes à la simulation, à recalibrer au pilote réel.

### Boucle poursuite-retrait (seuil 30 points)
```
boucle_probable : |pct1 − pct2| ≥ 30
```
La **direction** de la boucle (P1 avance / P2 recule, ou inverse) est
calculée mais **non affichée** — la boucle est nommée ENSEMBLE, jamais
imputée à une rive.

### Correction de style (L6)
```
HAUT si moyenne > 3,5 → correction −0,5
BAS si moyenne < 1,5 → +0,5
sinon MOYEN
styles « dissimulables » = {HAUT, BAS} → avertissement (non bloquant)
```

### Anti-verdict
`pct_compatibilite = None`, **jamais affiché**. Les 9 templates descriptifs
sont vérifiés par un garde lexical : « ta faute », « c'est toi », etc.
interdits ; aucun « % » dans les textes.
