## 1. Architecture deux dépôts (recommandation gravée)

| Dépôt | Visibilité | Contenu | Horizon |
|---|---|---|---|
| `wairyu-canon` | **PRIVÉ** | le canon : contenu machine, contrat, livrables, signaux, trames (jamais de formulation), gouvernance | immédiat |
| `wairyu-openscience` | PUBLIC | protocole, arbitrages, métriques de calibration agrégées, publications — **jamais** d'items, jamais de trames, jamais de seuils opérationnels | Phase 2+ |

Distinction fondatrice : **transparence-produit** (ce que l'utilisateur et la communauté peuvent auditer : doctrine, formats, gouvernance — publique) vs **transparence-stratégie** (le contenu même des instruments : privé, parce qu'un instrument exposé est un instrument contournable — pré-notation, coaching anti-détection, pollution des données de calibration).

## 2. Signal de sécurité consigné (trames 2.1 exposées)

Les 4 formulations DTM_N de la quête 2.1 sont présentes dans l'historique git public (commits `584f2c9`, `6f0a585`) : exposition à traiter — **rotation de formulation à programmer via Fiche de Mutation avant bêta** (codes gelés à jamais ; les énoncés, eux, tournent). Traitement complet : FM-018.

## 3. Checklist concepteur (opérations compte GitHub)

1. Privatiser le dépôt actuel (Settings → Danger Zone → Change visibility) — OU transférer vers `wairyu-canon` privé.
2. Fine-grained PAT : repository access = ce dépôt seul · Permissions = Contents: Read/Write · durée courte.
3. Fournir le jeton à la session d'exécution (jamais dans un fichier).
4. Révoquer le jeton en fin de session.
5. Activer le secret scanning + push protection (Settings → Code security).
6. Auditer les PAT existants (Settings → Developer settings).

## 4. Sécurité d'opération (gravée en Constitution [11] par FM-014 §4a)

Le jeton vit en variable d'environnement éphémère, transmis par helper d'identifiants en mémoire — jamais sur disque, jamais dans `.git/config`, jamais en argument. Un dépôt rouge ne part jamais ; le push est vérifié (la remote pointe sur notre commit). Le script `scripts/push-canon.sh` matérialise ces trois verrous.
